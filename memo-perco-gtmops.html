GTM strategy & operations

An agent-native cloud should be able to prove its own loop.

Avi Bedi / November 16, 2026 / Outside-in analysis

PERCO takes a founder's idea to a live product with domain, email, and production online. Its GTM systems should run on the same evidence loop it sells: every experiment instrumented, every signal turning into the next test.

What I noticed

PERCO.AI is an agent-native infrastructure cloud: describe the company, and the coding agent builds the product, domain, email, and production system, backed by NVIDIA Inception, AWS Startups, and Google for Startups. It is hiring a GTM Strategy & Operations Intern, remote-first or San Francisco, to design and run the systems that turn product signals into repeatable go-to-market experiments.

I'd test a self-hosting launch loop: every week, one new micro-product stood up end to end on PERCO targeting one niche, with acquisition, activation, and kill-or-keep decisions logged publicly. The infrastructure demonstrating itself is the strongest possible sales asset. Measure time-to-live-product and learnings shipped per week. That is an operations hypothesis, not a claim that PERCO's current experiments lack rigor.

What I'd do in my first 30 days

Days 1-7. Shadow one full idea-to-live run and document every manual step that still needs a human decision.

Days 8-20. Design the experiment registry: hypotheses, signals, thresholds, and the weekly review where kill-or-keep actually happens.

Days 21-30. Run two public loops end to end and publish the internal dashboard so prospects can watch the machine work.

I placed 2nd nationally in the SIFMA competition and built Prism AI, so evidence-driven iteration is how I already think. A summer 2027 internship running go-to-market as an instrumented system, for infrastructure that builds companies, is exactly where I want to be.
