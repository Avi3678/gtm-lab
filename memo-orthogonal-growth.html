Orthogonal / Growth

Sell the receipt, not the marketplace.

Avi Bedi / November 16, 2026 / Outside-in analysis

My read: for a marketplace where agents pay per API call, the convincing artifact is one transaction receipt: what the agent bought, what it cost, what it replaced.

What I noticed

Orthogonal is the data marketplace for agents: one balance, pay per call, hundreds of APIs behind one MCP or SDK, with providers listing once and earning per request. The founders come from payments at Coinbase, billing at Vercel and APIs at Google, and the careers page currently lists a Growth Lead; earlier this year they hired growth interns. The hard part of their GTM is two-sided: developers must believe integration is trivial, and API providers must believe agents will actually pay.

I'd test content built around a single worked transaction: an agent needs flight prices and company data, finds both through Orthogonal, pays cents, no API keys. Then the same story from the provider side: revenue from agents that never created an account. Serving both sides in one artifact is what marketplace content rarely does. One caveat: there is no intern posting today, so this note responds to the open growth role and past intern hiring, not a formal internship.

What I'd do in my first 30 days

Days 1-7. Run the product end to end as a developer. Map which provider categories are live and which agent frameworks the early users build on. Agree on one worked-example format.

Days 8-20. Publish one reviewed transaction story with a real (synthetic-data) receipt, plus a provider-side version. Post where agent builders actually read.

Days 21-30. Track signups and provider listings attributable to each piece. Report what the split says about which side needs the next story.

I build with APIs and agents daily at Prism AI, so I can write the worked example as a user rather than about users. That is usually the difference between content developers share and content they skip.
